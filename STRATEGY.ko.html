홀덤 도장: 무료로 오래 쓰이는 학습 게임을 만드는 전략

나상균 · 010-7529-5945 | 검토 기준 2026년 9월 13일

권고안

핵심 게임과 기초 교육은 무료로 유지하고, 웹앱에서 학습 효과와 재방문을 확인한 뒤 심화 콘텐츠를 한 번 구매하는 모델을 검토한다. 첫 목표는 매출이 아니라 “이 게임을 하고 나니 콜하는 이유를 설명할 수 있다”는 사용자 경험이다.

지금은 광고·구독·유료 칩을 넣지 않는다. 서버를 직접 운영하지 않는 구조를 유지하고, 개발 시간은 학습 콘텐츠의 정확성, 상대의 행동, 조작감, 복기에 쓴다. 앱 출시는 유입을 만드는 마법의 단계가 아니라 이미 검증된 경험을 더 편하게 사용하는 유통 채널로 본다.

현재 공개 주소는 유지한다. 다만 Vercel Hobby는 개인의 비상업적 이용에 한정된다. 광고, 유료 상품 연결 등 상업적 이용을 시작하기 전에 요금제·약관을 재확인하고 무료 정적 호스팅으로 옮기는 방안을 먼저 실행한다. 계정의 실제 요금제는 이번 검토에서 확인하지 않았다. Vercel Hobby

이 문서의 가격·일정·목표치는 실행을 위한 가설이다. 시장 평균이나 확보된 사용자 실적, 매출 예측이 아니다. 정책과 비용은 제출·결제 직전에 다시 확인한다.

1. 어떤 사람을 위한 어떤 제품인가

첫 고객은 규칙은 조금 알지만 매번 “왜 이 버튼을 눌러야 하는지” 막막한 성인 입문자다. 그다음은 친구들과 하는 게임 전에 포지션·팟 오즈를 연습하려는 사람이다. 전문 플레이어용 GTO 연구 도구와 정교한 수익 분석은 초기 약속에서 제외한다.

브랜드 한 문장: 한 판마다, 한 수 더.

설명 문장: AI와 가볍게 한 판. 그때의 선택을 돌아보고, 내일 다시 기억하는 한국어 홀덤 도장.

차별점은 화려한 칩 획득 연출보다 ‘플레이 → 당시 판단 복기 → 관련 원리 → 간격을 둔 재확인’이 끊기지 않는 것이다. 가입 없이 시작하고, 끊긴 판을 복원하고, 잘 모르는 용어를 즉시 이해할 수 있어야 한다. 나상균의 이름과 연락처는 도장 이야기·제작자 메뉴와 안내 페이지에 남긴다.

“실전 수익 보장”, “정확한 승률”, “GTO AI”, “모든 연령 이용 가능”처럼 현재 구현이나 심사 결과가 뒷받침하지 않는 문구는 사용하지 않는다.

2. 이번 버전에 실제로 반영한 것

영역구현이용자에게 생기는 변화
게임 기반행동 순서, 최소 레이즈, 짧은 올인, 사이드팟, 초과 칩 반환, 헤즈업잘못된 규칙을 게임으로 익히는 문제를 줄임
플레이4인 코치 연습, 6인 챔피언십, 1:1배우기와 힌트 없는 도전을 오갈 수 있음
감각카드·칩·체크·폴드·내 차례·완료 효과음, 음량, 음소거화면을 계속 읽지 않아도 흐름을 알아챔
교육10개 과정, 36개 상황 문제, 169칸 입문 차트, 족보 예시, 확률 실험실읽고 계산하고 눌러보는 연습을 함께 제공

기록기기 내 저장, JSON 백업·가져오기, 가져오기 전 기록 복원서버 없이도 기기 이동과 이전 기록 회복 가능
유입같은 문제 링크 공유, 공통 일일 문제, 검색용 입문 가이드친구가 바로 같은 상황을 풀어볼 수 있음
앱 기반오프라인 PWA, 아이콘, 독립 게임 엔진, Capacitor 설정같은 코드를 네이티브 앱에 재사용할 출발점

효과음은 외부 음원 다운로드 없이 기기에서 합성한다. 배경음악은 추가하지 않았다. 음량·음소거를 유지하고 백그라운드에서는 멈춰 학습에 집중하게 한다. 처음 이용할 때 효과음 선택이 보이며, 이전 버전에서 꺼 두었다면 그 선택을 유지한다.

콘텐츠 수를 늘린 것만으로 학습 효과가 증명되지는 않는다. 실제 사용자의 사전·사후 확인과 며칠 뒤 재확인이 다음 단계다.

3. 서버 비용 0원을 유지하는 운영 설계

운영 구조는 ‘정적 파일 배포 → 브라우저에서 게임·확률 계산 → 기기에 기록 저장’이다. 서버 측 게임 연산, 데이터베이스, 유료 AI API를 호출하지 않는다. 새 문제는 코드와 함께 배포한다.

기능비용을 억제하는 선택받아들여야 할 한계
AI 상대·코치기기에서 규칙과 근사 계산 수행서버의 대형 모델·솔버 수준 아님
학습 저장브라우저 저장 + 사용자 백업 파일자동 동기화·계정 복구 없음
콘텐츠 갱신정적 빌드와 호스팅 배포작성·검수 시간은 계속 필요
일일 도전·공유날짜별 문제와 문제 번호 링크신뢰 가능한 전 세계 순위 없음
오프라인서비스 워커 캐시최초 준비에 접속 필요, 기기가 캐시를 정리할 수 있음
의견 수집제작자 연락처, 사용자가 직접 전달하는 피드백자동 집계·대규모 고객 지원 없음

무료 호스팅 이전의 우선 검토 대상은 Cloudflare Pages의 정적 배포다. 공식 문서는 정적 요청을 무료·무제한으로 안내하며 Free의 월 빌드 제한은 500회다. Functions를 쓰면 별도 사용량 체계가 생기므로 현재 앱은 정적 파일만 올린다. 무료 요금제도 약관·서비스 변경·기술적 제한이 있으므로 영구 무비용을 계약처럼 약속할 수는 없다. 정적 요청 요금, Pages 제한

이전 순서: 저장소 연결 → 빌드 npm run build, 결과 dist → 새 주소에서 오프라인·카드·백업 검증 → canonical·공유 링크·사이트맵 교체 → 기존 사용자가 이전 주소에서 백업을 내려받도록 안내 → 새 주소에서 가져오기. 브라우저 저장은 도메인별이므로 주소만 바꾸면 기록이 자동 이동하지 않는다. vercel.app 주소 자체를 Cloudflare로 옮길 수는 없으며 새 무료 주소나 소유 도메인이 필요하다.

현재 HTML의 /Index.html 호환 경로, 개인정보 문서 링크, 공유 이미지 주소도 함께 점검한다. _headers와 _redirects를 준비해 두었지만 실제 Cloudflare 계정 연결·이전 배포는 아직 하지 않았다. 현재 Vercel 주소를 유지하기 위한 결정이다.

도메인 구매, 개발자 계정, Mac·테스트폰, 등급 분류, 결제 수수료와 콘텐츠 제작 시간은 서버 비용과 별개다. ‘서버 운영비 0원’은 가능하지만 ‘사업 비용 전체 0원’과 같지는 않다.

4. 돈은 어떻게 벌 것인가

방식적합도판단
핵심 무료 + 심화 문제집·해설팩 단품 판매높음, 검증 후기초 접근성을 유지하면서 잘 만든 콘텐츠에 비용을 받음
선택적 후원보조 수단불규칙한 수입. 호스팅 상업 조건·플랫폼 결제 규칙 확인 필요
별도의 유료 완결 앱중간자체 이용권 서버를 줄일 여지가 있지만 무료 웹과 차이가 분명해야 함
교육용 테이블·동호회용 자료 라이선스중장기소수 구매자에게 가치가 크지만 지원·콘텐츠 사용 조건 필요
배너·전면·보상형 광고초기 낮음몰입 방해, 개인정보 SDK와 정책 관리, 적은 이용량에서의 낮은 실익
매월 구독초기 낮음계속되는 새 가치와 구매 복구·환불·구독 관리 부담
유료 칩·현금 교환·상금 대전채택하지 않음학습 목적과 충돌하고 규제·운영·보안 부담이 큼

추천하는 첫 유료 상품은 ‘계속 쓰는 기능’보다 완결된 심화 코스다. 예를 들어 리버 판단 50제 + 조건별 해설 + 7일 재확인 문제 + 인쇄 가능한 복기 워크시트. 지금 무료인 기초 규칙, 팟 오즈, 기본 게임과 복기를 유료로 잠그지 않는다.

가격은 우선 4,900~9,900원 단품의 지불 의향을 인터뷰로 확인하는 가설로 둔다. 결제 버튼을 먼저 만들지 말고 예시 5문제와 실제 상품 목차를 보여 준다. 10명 중 몇 명이 “좋다”는지보다, 어떤 문제를 해결했고 어떤 내용을 실제로 구매하겠다는지 확인한다. 예약 결제나 자동 청구는 현재 추가하지 않았다.

산술 예시: 월간 이용자 1,000명 × 구매 비율 2% × 7,900원 = 월 158,000원 총판매액. 이 수치들은 가정이며 세금·수수료·환불·제작비를 빼기 전이다. 기존 구매자에게 같은 단품을 매달 다시 판매할 수 없으므로 반복 매출 예측으로 사용하면 안 된다.

서버 없는 웹앱에 유료 콘텐츠를 모두 넣고 버튼만 잠그면 코드 열람으로 우회할 수 있다. 숨겨진 비밀번호·localStorage의 결제 여부로 보호했다고 홍보하지 않는다. 초기에는 외부 판매 서비스가 결제와 파일 전달을 맡는 완결 자료가 운영하기 쉽지만, 해당 서비스 수수료·구매자 정보 처리·환불 안내를 검토해야 한다. 앱 안에서 디지털 콘텐츠를 판매하거나 외부 구매를 연결할 때는 해당 국가와 스토어의 당시 결제 규칙을 별도로 확인한다.

Google은 구매 확인과 중요 로직을 안전한 백엔드에서 처리하도록 권고한다. 서버 없이 복잡한 인앱 구독과 확실한 불법 복제 방지까지 모두 달성하겠다는 약속은 하지 않는다. 플랫폼 결제를 쓰더라도 복원, 보류 결제, 환불과 재설치를 테스트해야 한다. Google Play 결제 보안

광고를 넣게 되더라도 학습 중 팝업과 판 사이 강제 광고는 우선 제외한다. 특히 Google Play의 도박 광고 정책은 모의 도박 콘텐츠가 있는 앱에 실제 도박 광고를 싣는 경우를 제한한다. 이 조항을 ‘모든 모의 포커 게임이 금지’라는 뜻으로 확대하지 않는다. 카지노·실제 도박 유입형 광고는 이 제품의 수익원으로 선택하지 않는다. Google Play 관련 정책

5. 사람들이 찾아오고 다시 쓰게 하는 방법

초기 약속은 ‘하루 5분, 한 가지 판단을 설명할 수 있게’다. 무제한 체류 시간이나 연속 접속 압박을 성공으로 보지 않는다. 게임 한 판과 복기 하나로 만족스럽게 끝낼 수 있어야 한다.

검색용 콘텐츠는 매주 하나씩, 질문 → 예시 → 계산 → 흔한 오해 → 바로 풀 문제 형태로 만든다. 이번 입문 가이드와 사이트맵은 출발점이며 검색 노출·순위가 보장되지는 않는다. 별도 글을 만들 때 같은 내용을 제목만 바꿔 반복하지 않는다.

순서콘텐츠 제목연결할 실습
1팟 100에 50 베팅, 왜 25%가 필요할까?q5 + 팟 오즈 실험실

짧은 영상은 같은 예시를 재사용한다. 0~3초에 문제, 3~10초에 선택지, 10~25초에 이유, 마지막에 같은 문제 링크를 둔다. 제목 예시: “콜 50, 필요한 확률은 50%일까?” 승리 장면과 돈 이미지만 반복하지 않는다.

첫 배포 문안 초안: “홀덤 버튼은 누르는데, 왜 누르는지 헷갈렸다면. AI와 연습하고 내 선택을 복기하는 무료 한국어 게임을 만들었습니다. 가입 없이 한 판, 팟 오즈는 직접 바꿔 보며 배울 수 있어요. 가장 이해하기 어려웠던 설명을 알려주세요. — 나상균”

커뮤니티에는 규칙을 확인한 뒤 해당 질문에 도움이 되는 설명과 문제 하나를 공유한다. 연락처 수집이나 반복 홍보 대신 소규모 사용자 10명에게 설명이 통하는지 먼저 본다. 외부 글·메시지·영상 게시를 이번 작업에서 대신 실행하지 않았다.

앱 아이콘과 브랜드는 유지하되, 스토어 스크린샷은 테이블 1장, 선택 이유 1장, 복습·성장 1장, 오프라인·무료 1장으로 구성한다. “한 판마다, 한 수 더”와 실제 화면이 같은 약속을 해야 한다.

6. 학습 효과를 어떻게 확인할 것인가

가장 중요한 지표는 한 판과 그 판의 복기를 완료하고, 같은 원리를 며칠 뒤 새 예시에서도 설명하는 사람 수다. 승률·순보유 칩·XP는 실제 실력의 증명으로 쓰지 않는다.

첫 사용성 시험은 성인 입문자 10명 내외로 진행한다. 설명 없이 게임을 열게 하고 다음을 관찰한다: 내 카드 찾기, 체크와 콜 구별, 한 판 완료, 복기 찾기, 팟 오즈 문제 설명, 다음날 재사용 이유. 이름·전화번호를 포함한 플레이 로그를 모을 필요는 없다.

진행 기준의 초안: 10명 중 8명이 도움 없이 첫 행동, 6명이 첫 판과 복기 완료, 5명이 팟 오즈 계산 이유를 설명. 7일 뒤 다른 수치의 문제에서도 설명하는지 다시 본다. 작은 표본은 방향 확인용이며 통계적 성과나 외부 홍보의 근거로 과장하지 않는다.

기기 안의 ‘주제별 정답률’은 그 기기에서 누적된 응답이다. 운영자가 전체 사용자의 재방문율·학습 효과를 볼 수 있는 분석 서버는 없다. D1·D7 유지율을 자동 수집했다고 표현하지 않는다. 초기에는 동의한 시험 참여자의 인터뷰와 사용자가 직접 공유한 요약만으로 판단한다. 이후 필요하면 수집 범위를 정한 뒤 무료 호스팅 분석이나 동의 기반 이벤트 수집을 별도 검토한다.

문제 검수 규칙: 상황의 인원·스트리트·스택·선행 행동을 명시하고, 계산 문제는 정확한 식을 갖춘다. 전략 문제는 전제를 제한한다. 정답 하나가 성립하지 않으면 선택지 문구를 바꾸거나 토론형 해설로 전환한다. 코드 테스트와 홀덤 경험자의 내용 검토는 역할이 다르다. 현재 콘텐츠는 외부 전문가 인증을 받은 것이 아니다.

9. 출시 순서와 운영 원칙

권장 순서는 무료 웹/PWA 개선 → 실제 사용성·학습 확인 → 한국 등급 및 계정 조건 확인 → Android 시험 → iOS 검토 → 심화 단품 수익화다. 유료화가 웹에서 먼저 타당해지면, 호스팅 상업 조건과 판매 서비스 정책부터 충족한 후 진행할 수 있다.

현재 수익화·호스팅 이전·네이티브 스토어 등록·외부 홍보 게시·계정 생성·비용 결제는 실행하지 않았다. 제품의 무료 핵심을 완성하고 검증할 수 있도록 구현과 전략을 준비했다. 최종 결정은 ‘사람들이 실제로 더 잘 이해하고 다시 찾는가’라는 증거를 기준으로 한다.
